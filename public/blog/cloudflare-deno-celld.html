      Cloudflare가 Deno 팀을 품었다 — 진짜 핵심은 celld다

      같은 코드를 Cloudflare 클라우드와 기관 자체 서버 중에서 골라 실행한다. 2026년 10월 9일의 발표를 바이브코딩, AI 에이전트, 공공기관 폐쇄망의 눈으로 읽는다.

      신성진 · 한국데이터사이언티스트협회 2026. 10. 12

      바이브코딩으로 만든 AI 에이전트를 어디에서 운영할 것인가. 이 질문에 대한 선택지가 조용히 하나 늘었습니다. 2026년 10월 9일(미국 현지), Cloudflare와 Deno는 Deno 팀 전원이 Cloudflare에 합류한다고 양사 공식 블로그에서 동시에 발표했습니다. 외신은 인수로 보도했고, 금액은 비공개입니다. 그런데 이 뉴스를 "런타임 회사가 팔렸다" 정도로 읽으면 가장 중요한 단어를 놓칩니다. 발표문의 무게 중심은 Deno라는 런타임이 아니라 celld라는 오픈소스에 실려 있습니다.

      01 / 무슨 일이Deno 팀 전원이 Cloudflare에 합류했다

      Deno는 Node.js 창시자 라이언 달(Ryan Dahl)이 공동 설립한 JavaScript·TypeScript 런타임 회사입니다. Node.js를 만든 사람이 Node.js의 설계 후회를 고쳐 다시 만든 런타임이 Deno였고, 그 팀이 이제 통째로 Cloudflare로 들어갑니다. 발표에 따르면 앞으로의 개발은 별도의 런타임과 호스팅이 아니라 Workers 공통 플랫폼에 집중되고, 목표는 Workers 프로그래밍 모델을 서버 구축의 기본 방식으로 만드는 것입니다.

      기존 Deno 사용자에게는 실질적인 변화가 따라옵니다. Deno 런타임은 1년간 버그·보안 업데이트를 받은 뒤 Deno 팀의 개발이 종료되고(오픈소스로는 유지), Deno Deploy는 6개월 후 종료됩니다. JSR 패키지 레지스트리는 계속 운영됩니다. Deno 기반 서비스를 운영 중인 조직이라면 지금부터 이전 계획을 세워야 합니다.

      02 / celld란Cloudflare 앱을 우리 서버에서 돌리는 오픈소스

      celld는 Deno가 2026년 8월 공개한 오픈소스 데몬입니다. 하는 일을 한 문장으로 줄이면 이렇습니다. Cloudflare Workers·Durable Objects 방식으로 만든 애플리케이션을 Cloudflare 바깥, 즉 자체 인프라에서 분산 운영할 수 있게 해준다. 객체 하나가 자체 SQLite DB를 가진 작은 서버, 즉 셀(cell)이 되고, 장기 상태는 운영자가 소유한 S3 호환 버킷에 저장됩니다.

      그리고 이번 발표의 기술적 핵심이 바로 여기 있습니다. Cloudflare는 자사의 오픈소스 Workers 런타임 workerd와 celld를 통합해, 자체 호스팅을 비공식 우회로가 아닌 정식 지원 방식으로 만들겠다고 밝혔습니다. 지금까지 Workers 코드는 사실상 Cloudflare 네트워크에서만 "제대로" 돌았습니다. 앞으로는 같은 코드가 기관 서버실에서도 1급 시민으로 돈다는 선언입니다.

      03 / 구조 변화배포 대상이 아니라 실행 방식을 표준화한다

      구조로 보면 변화가 선명합니다. 지금까지의 흐름은 바이브코딩으로 코드를 쓰고, wrangler로 Workers에 배포하고, Cloudflare 네트워크에서만 실행하는 외길이었습니다. 발표가 지향하는 흐름은 갈림길입니다.

      발표가 지향하는 미래의 단순화 개념도 — 모든 Cloudflare 서비스가 그대로 호환된다는 의미는 아니다.

      저는 이 변화를 이렇게 요약합니다. Cloudflare는 지금까지 배포 대상이었습니다. 이제는 실행 방식이 되려고 합니다. "우리 서버에 올려라"가 아니라 "어디서 돌리든 이 방식으로 돌려라"입니다. 서버를 임대하는 회사에서, 서버를 운영하는 방식 자체를 표준화하려는 회사로의 확장입니다.

      04 / 에이전트 관점에이전트는 모델 API만으로 돌아가지 않는다

      이 인수가 AI 에이전트와 무슨 상관이냐는 질문이 나올 수 있습니다. 전부 상관있습니다. LLM은 아무것도 못한다에서 썼듯, 에이전트는 모델에 도구와 실행 환경을 쥐여줄 때 완성됩니다. 에이전트를 실제로 운영하려면 모델 API 호출 말고도 실행환경, 데이터베이스, 상태 저장, 작업 큐, 사용자별 세션 관리가 전부 필요합니다. Cloudflare의 구성요소는 이 필요와 정확히 포개집니다.

      구성요소에이전트에서 하는 일
      WorkersAPI와 실행 로직
      Durable Objects에이전트별 상태·세션 유지
      D1 / R2업무 데이터와 파일 저장
      Queues비동기 작업 처리
      AI 모델 API판단·분석·생성

      라이언 달 본인도 Durable Objects가 에이전트 운영에 특히 유용하다고 강조했습니다. 객체 하나가 상태를 가진 작은 서버라는 Durable Objects의 모델은, 직원 한 명당 에이전트 하나라는 구도와 자연스럽게 맞아떨어집니다. 기관 직원 100명이 각자 자기 에이전트를 갖고, 각 에이전트가 자기 작업 상태와 메시지 이력을 들고 있는 구조를 이 프로그래밍 모델로 설계할 수 있습니다.

      단서기술이 합쳐진다고 완성형 에이전트 플랫폼이 자동으로 나오는 것은 아니다. 인증, 권한, 보안, 운영관리는 여전히 설계해야 할 몫으로 남는다.

      05 / 연속 인수2026년, 세 번의 인수

      이번 건만 떼어 보면 놓치는 그림이 있습니다. Cloudflare는 올해 세 번 움직였습니다.

      2026.01.16
      Astro
      프론트엔드·웹 프레임워크 — 웹사이트 제작 역량 확보
      2026.06.04
      VoidZero
      Vite 등 빌드 도구 — 코드 빌드·개발 도구 역량 강화
      2026.10.09
      Deno 팀
      서버 실행·자체 호스팅(celld) — 실행 계층 장악

      웹 제작, 빌드, 실행, 운영. 개발 생태계의 수직 통합입니다. AI가 코드를 쓰는 시대에 프레임워크·빌드 도구·런타임을 한 회사가 쥔다는 것은, 바이브코딩의 기본 경로 자체를 자사 생태계로 깔겠다는 뜻입니다. 코딩에이전트가 "웹 서비스 만들어줘"라는 요청을 받았을 때 자연스럽게 선택하는 스택이 Astro + Vite + Workers가 되는 미래를 그리고 있는 겁니다.

      06 / 폐쇄망 관점공공기관에는 무엇이 달라지나

      CDSA가 이 발표를 유심히 본 이유는 따로 있습니다. 우리는 행정망·폐쇄망에서 돌아가는 바이브코딩을 계속 다뤄 왔습니다. 그 관점에서 이 발표는 하나의 오래된 벽에 균열을 내는 사건입니다. 지금까지 외부 클라우드가 막힌 조직에서 Workers 스타일의 서버리스 앱은 사실상 선택지가 아니었습니다. workerd와 celld의 통합이 약속대로 진행되면, 외부망에서 바이브코딩으로 만들고 검증한 에이전트를 같은 코드 그대로 내부망 서버에서 운영하는 경로가 생깁니다.

      실무 구도는 이렇게 정리할 수 있습니다. 외부 클라우드 사용이 허용된 업무는 Cloudflare에서 신속하게 배포하고, 기관 내부 데이터를 다루는 업무는 자체 서버용 Workers 실행환경을 검토합니다. 개발 환경과 운영 환경의 차이가 줄어들면 기관 간 시스템 이전 가능성도 함께 올라갑니다. A기관에서 만든 에이전트를 B기관 서버로 옮기는 일이, 환경 전체를 재구축하는 일에서 설정을 바꾸는 일로 내려올 수 있습니다.

      주의폐쇄망 도입은 아직 별도 검증 과제다. celld는 D1·R2·Queues 같은 바인딩을 자체 구현한다고 밝히지만, S3 호환 스토리지가 필요하고, Cloudflare 관리형 서비스의 인증·운영 기능까지 똑같이 작동한다고 보기는 어렵다. 통합 자체도 발표 단계이며 완성도·호환성은 앞으로 확인해야 한다.

      07 / 판단바이브코딩 결과물이 '운영 시스템'이 되는 길

      제가 가장 주목하는 대목은 따로 있습니다. 바이브코딩의 다음 단계에 대한 이야기입니다. 지금까지 비개발자가 AI와 함께 만든 결과물은 대체로 개인 실습용에 머물렀습니다. 잘 되면 링크 공유까지. 그런데 "AI로 만들고, 클라우드든 자체 서버든 비슷한 방식으로 실행하고, 여러 에이전트의 상태와 작업을 관리한다"는 그림이 실현되면, 바이브코딩 결과물이 기관이 실제 운영하는 시스템으로 올라설 통로가 넓어집니다.

      Cloudflare는 서버를 임대하는 회사에서,
      서버를 운영하는 방식 자체를 표준화하려는 회사로 가고 있다.

      물론 현재는 방향을 공식 발표한 단계입니다. workerd와 celld 통합의 완성도, 바인딩 호환성, 운영 도구의 성숙도는 전부 앞으로의 확인 과제입니다. 그래도 질문 하나는 오늘부터 유효해졌습니다. 여러분의 기관·회사라면, 바이브코딩으로 만든 AI 에이전트를 어디에서 운영하시겠습니까. 퍼블릭 클라우드인가, 자체 서버인가, 아니면 업무별로 둘 다인가. 이 질문에 답을 준비해 두는 조직과 그렇지 않은 조직의 거리는, 통합이 완성되는 날 한 번에 벌어질 겁니다.
