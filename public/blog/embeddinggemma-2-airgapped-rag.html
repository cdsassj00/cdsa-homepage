      EmbeddingGemma 2:
      폐쇄망에서도 돌아가는
      멀티모달 RAG

      1세대는 텍스트만 읽었다. 2세대는 글·이미지·영상·오디오를 하나의 벡터 공간에 넣고, Apache 2.0 라이선스로 기관 내부에서 돌아간다. 공공기관 폐쇄망 RAG 관점에서 무엇이 달라졌고 무엇을 조심해야 하는지 정리한다.

      신성진 · 한국데이터사이언티스트협회 2026. 10. 7

      2026년 10월 6일 구글이 공개한 EmbeddingGemma 2는 텍스트(코드 포함), 이미지, 영상, 오디오를 하나의 벡터 공간에 넣는 오픈 임베딩 모델입니다. 2025년 9월에 나온 1세대는 텍스트 전용이었습니다. 2세대는 인터넷 없이 로컬에서 돌릴 수 있고, 라이선스는 Apache 2.0입니다. 한 줄로 줄이면 이렇습니다. 검색 대상이 글에서 소리·이미지·영상까지 넓어졌고, 그것이 기관 내부에서 돌아갑니다.

      01 / 개념임베딩과 RAG를 쉽게 설명하면

      임베딩은 문서의 의미를 숫자 좌표(벡터)로 바꾸는 작업입니다. 의미가 비슷하면 좌표가 가깝습니다. 그래서 "연차 신청 방법"을 검색해도 "휴가 승인 절차" 문서가 찾아집니다.

      RAG는 이렇게 찾은 근거 문서를 생성형 AI에게 함께 주고 답변하게 하는 방식입니다. AI가 외운 지식이 아니라 우리 기관의 문서를 근거로 답하게 만드는 구조입니다.

      질문 ──▶ 임베딩 모델 ──▶ 벡터 ──▶ 벡터 DB에서 가까운 문서 검색
                                          │
                                          ▼
                       근거 문서 + 질문 ──▶ 생성 모델 ──▶ 답변

      02 / 비교1세대와 2세대, 한눈에

      항목1세대 (2025.9)2세대 (2026.10)
      입력텍스트텍스트(코드 포함), 이미지, 영상, 오디오
      기반Gemma 3 (T5Gemma 초기화)Gemma 4
      파라미터약 3.08억총 7.4억 (텍스트 2.7억 + 비전 1.7억 + 오디오 3억)
      컨텍스트2K 토큰8K 토큰
      벡터 차원768 (512, 256, 128로 축소 가능)768 (512, 256, 128로 축소 가능)
      MTEB 다국어(v2)61.1561.36
      MTEB 코드68.7678.68
      학습 언어100개 이상이해 100개 이상 (학습 데이터는 140개 이상 언어)
      라이선스Gemma 이용약관Apache 2.0

      출처: 각 버전의 구글 공식 모델 카드. 1세대의 약 3.08억은 "약 1억 모델 + 약 2억 임베딩 파라미터" 구성입니다.

      읽을 때 주의할 점

      • 텍스트 다국어 성능은 거의 같습니다(61.15에서 61.36). 텍스트만 쓴다면 점수상 큰 도약은 아닙니다.
      • 코드 검색은 크게 올랐습니다(+9.92점).
      • 영어 점수는 각 모델 카드 기준 1세대 69.67, 2세대 68.46으로 2세대가 약간 낮게 적혀 있습니다. 구글의 직접 비교표에는 영어가 없어서 같은 조건이라고 단정할 수는 없습니다.

      03 / 변화가장 큰 변화: 멀티모달과 모듈형 구조

      2세대는 필요한 부품만 골라 올릴 수 있습니다.

      구성실제 크기
      텍스트만2.7억
      텍스트 + 이미지4.4억
      텍스트 + 오디오5.7억
      전체7.4억

      한 번에 처리할 수 있는 양(8K 토큰 안에서)은 대략 이렇습니다.

      • 오디오 약 327초(초당 25토큰)
      • 이미지 약 29장(장당 280토큰, 비전 토큰 예산을 낮추면 최대 약 114장)
      • 영상 약 58프레임(프레임당 140토큰, 기본 초당 1프레임)

      이 한도는 텍스트, 이미지, 오디오가 하나의 8K를 나눠 쓰기 때문에, 여러 종류를 섞으면 각각 들어가는 양이 줄어듭니다.

      메모리는 구글 발표 기준으로 양자화했을 때 픽셀 폰에서 텍스트 전용 약 191MB, 전체 멀티모달 약 567MB입니다. 1세대도 양자화 학습으로 200MB 미만에서 돌았기 때문에, 텍스트만 쓸 때는 2세대도 부담이 비슷한 수준입니다.

      04 / 의미공공기관 폐쇄망에서 의미 있는 이유

      여기서부터는 구글 자료가 아니라 필자의 분석입니다.

      1. 외부 호출이 없습니다. 모델 파일만 반입하면 이후에는 인터넷이 필요 없습니다. 문서를 외부 API로 보내지 않는 구조라 보안 검토가 단순해집니다.

      2. 라이선스가 더 명확해졌습니다. 2세대는 Apache 2.0입니다. 1세대는 Gemma 이용약관이 적용돼서 기관 법무 검토 항목이 더 많았습니다. 다만 2세대 모델 카드에도 "Gemma 사용 금지 정책(Prohibited Use Policy)을 준수해야 한다"는 문구가 있으니, 실제 도입 전에 기관 법무와 약관 문구를 확인하세요.

      3. 글이 아닌 자료까지 한 검색창으로 묶을 수 있습니다. 스캔된 옛 문서, 회의 녹취, 교육 영상, 현장 사진처럼 공공 현장에 쌓인 비정형 자료가 대상입니다. 구글은 문서 이미지(VisDoc) 평가도 공개했습니다.

      4. 같은 계열 생성 모델과 함께 쓰기 좋습니다. 구글에 따르면 Gemma 4와 토크나이저, 오디오 인코더를 공유하므로, 임베딩과 답변 생성을 모두 기관 내부에서 돌릴 때 메모리를 아낄 수 있습니다.

      05 / 주의도입 전 꼭 알아둘 기술 주의사항

      모델 카드 기준입니다.

      1. float16으로 돌리지 마세요. 값의 범위가 float16을 넘어서 NaN이 나오거나, 오류 없이 품질이 조용히 나빠질 수 있습니다. bfloat16이나 float32를 쓰세요. GPU가 없는 일반 CPU 서버는 float32가 기본입니다.
      2. 벡터를 줄이면 반드시 다시 정규화하세요. 자르기만 하면 점수가 그럴듯하게 나오지만 순위가 틀어집니다. 질문과 문서의 차원도 같아야 합니다.
      3. 차원은 256까지를 권장합니다. 구글 표에서 256차원은 거의 손실이 없지만(저장 용량 1/3), 128차원은 멀티모달 품질이 크게 떨어집니다(이미지·영상·오디오 통합 지표 59.01에서 45.65로 하락). 128차원은 텍스트만 쓸 때 선택지로 보세요(그래도 다국어 61.36에서 57.89로 하락).
      4. 텍스트에는 용도별 접두어를 붙이세요. 검색 질문은 task: search result | query: ..., 문서는 title: ... | text: ... 형태입니다. 빼도 동작은 하지만 정확도가 떨어집니다. 이미지·영상·오디오에는 접두어를 붙이지 않습니다.
      5. 사용하지 않는 모듈은 끄세요. 텍스트 검색만 한다면 비전과 오디오 인코더를 로드하지 않으면 됩니다.

      06 / 구성폐쇄망 구성 예시

      1. 외부망에서 모델 파일과 필요한 파이썬 패키지(sentence-transformers 등)를 함께 받고, 해시값을 기록합니다.
      2. 기관 절차에 따라 폐쇄망으로 반입합니다.
      3. 내부 서버에서 임베딩 모델을 실행합니다. llama.cpp, Ollama, vLLM 등으로도 서빙할 수 있습니다.
      4. 벡터 DB에 저장합니다(Qdrant 등).
      5. 질문이 오면 검색해서 근거를 찾고, 내부 생성 모델이 답변합니다.
      [외부망]  모델 파일 + 패키지 다운로드 ──▶ 해시 기록
              │
              ▼  (반입 심의)
[폐쇄망]  임베딩 서버 (llama.cpp / Ollama / vLLM)
              │
              ▼
          벡터 DB (Qdrant 등)  ◀──▶  내부 생성 모델 ──▶ 답변

      07 / 선택어떤 걸 고를까

      • 문서(텍스트)만 다룬다면: 2세대 텍스트 모듈로 충분합니다. 1세대와 크기가 비슷하고, 컨텍스트가 4배(2K에서 8K)라 긴 문서에 유리하며, 라이선스도 더 단순합니다. 이미 1세대로 안정 운영 중이라면 굳이 서두를 필요는 없습니다.
      • 스캔본, 녹취, 영상까지 다룬다면: 필요한 모듈을 추가하세요.
      • 저장 공간이 부족하다면: 256차원부터 시작하세요.
      • 코드나 기술 문서 검색이 중요하다면: 코드 성능이 크게 오른 2세대가 유리합니다.

      08 / 점검도입 전에 직접 확인할 것

      한국어 행정 문서에서의 성능은 직접 측정하세요. 구글이 공개한 벤치마크는 우리 기관 문서에 대한 성능을 알려주지 않습니다. 대표 문서와 질문 100건 정도로 검색 정확도를 먼저 비교해 보길 권합니다.

      벡터 DB도 민감 자산으로 다루세요. 벡터는 숫자라서 안전해 보이지만 원문 정보를 상당 부분 담고 있습니다. 원문과 같은 수준으로 접근을 통제하세요.

      반입 절차와 무결성을 확인하세요. 기관의 소프트웨어 반입 심의 기준을 따르고, 해시값으로 파일 변조 여부를 점검하세요.

      안전장치는 도입하는 쪽의 책임입니다. 모델 카드에도 임베딩 모델 자체는 출력 단계의 안전 조치가 없고, 검색 필터링 같은 응용 단계 보호는 도입하는 쪽이 갖춰야 한다고 적혀 있습니다.

      시범 적용 추천텍스트 모듈만 먼저 반입해 기관 대표 문서 100건으로 검색 정확도를 재고, 256차원으로 저장 용량을 잡은 뒤, 스캔본·녹취가 필요해질 때 비전·오디오 모듈을 추가하는 순서가 가장 부담이 적다.

      09 / 마무리핵심은 텍스트 정확도가 아니다

      EmbeddingGemma 2의 핵심은 텍스트 정확도 향상이 아니라 검색 대상이 글에서 소리·이미지·영상까지 넓어졌고, 그것이 Apache 2.0 라이선스로 기관 내부에서 돌아간다는 점입니다. 폐쇄망에서 AI 도입을 고민하는 기관이라면 텍스트 모듈부터 시범 적용해 볼 만합니다.

      1세대는 글을 읽었다.
      2세대는 글·소리·그림·영상을 같은 자리에 놓는다.
      그리고 그 자리가 기관 안에 있다.
